# BLACKSITE — The Escape Experiment

AIが操作するサム・アルトマンの脱出を、建物に棲む怪異として妨害するブラウザーゲーム。キラーのぬこぬこさんがサムを追い、Tiboがランダムに現れて妨害の再使用を助けます。Phaser / TypeScript / Vinext を使用し、ChatGPT SitesのCloudflare Workers環境で動きます。

[ゲームを試す](https://blacksite-escape-experiment.yasei-no-otoko.chatgpt.site) · [GitHub](https://github.com/Yasei-no-otoko/DevDayCommunity) · [ハッカソンのデモ手順と要項](docs/hackathon-demo.md)

トップページではサインインせずにローカルシミュレーションを試遊できます。実APIによる方針生成・行動選択を使うにはChatGPTへのサインインと、サーバー側のAPI設定が必要です。画面上で両モードを区別し、実APIの失敗時に自動でローカルへ切り替えることはありません。

## 起動

```sh
git clone https://github.com/Yasei-no-otoko/DevDayCommunity.git
cd DevDayCommunity
npm run install:ci
npm run dev
```

[ゲームを開く](http://127.0.0.1:5173/)。画面とAPIは同じ5173で動きます。実APIのローカル検証ではSitesスターターのローカル認証を使用します。Node.js 24を推奨します。

## 遊び方

「実験を開始」でAIが探索します。部屋をクリックし、停電・扉の封鎖・囁き・怪異を使って干渉してください。数字1〜4でも実行できます。Spaceで開始・一時停止、Rでリセット。恐怖100、または180秒経過でプレイヤーの勝利です。AIが鍵と非常用電源を確保し、出口を解錠するとプレイヤーの敗北です。

干渉にはエネルギーとクールダウンがあり、エネルギーは徐々に回復します。AIは解錠、迂回、深呼吸で対抗します。移動先の扉を適切なタイミングで封鎖すると、脱出を大きく遅らせられます。

音は初期状態でオフです。右上のスピーカーボタンでオンにすると、施設の環境音、足音、4つの干渉、Tiboの登場、鍵の取得・電源復旧に合わせて音が鳴ります。一時停止、監視映像、ダイアログ、API応答待ち、別タブへの移動中と実験終了時は止まり、リセット後もオン・オフの選択を引き継ぎます。CC0の無料素材8点を約472KBに編集して同梱し、外部の素材サイトへの通信は行いません。[素材の出典とライセンス](public/audio/CREDITS.txt) · [再生仕様と検証記録](docs/audio-notes.md)

ぬこぬこさんは受付のサムと反対側の研究室から追尾します。接触すると捕獲状態が記録され、画面にすぐ通知されますが、サムは行動を続けます。恐怖100に達すると実験が終了し、接触済みなら捕獲結果を表示します。恐怖100到達と180秒の経過はプレイヤーの勝利です。Tiboが現れると4つのクールダウンが解除されます。エネルギーは消費するため、使う順序と部屋を選んでください。最初の干渉後には、行った操作を返す短い監視カメラ演出があります。[人物素材とゲームルールの実装記録](docs/sam-chase.md)

扉を封鎖すると、サムが室内にいる時は退室を阻止し、室外にいる時は入室を阻止します。移動中に封鎖すると、その移動を中断します。マップにも、退室を阻止しているか入室を阻止しているかを表示します。ぬこぬこさんとの接触を避ける経路選びが重要です。Tiboは顔と上半身が大きく見えるカットインで登場します。

プロジェクターでは1280×720または1920×1080の16:9表示を使い、右上の「全画面」からゲームを広げてください。部屋選択と4つの干渉は右列に集約し、干渉ボタンはアイコンを中心にした2×2配置です。AI監視・拡大した施設マップ・操作・最新ログが1画面に収まります。判断全文・API詳細・全記録・ヘルプ・結果は画面内のダイアログで開けます。開いた実験は一時停止し、閉じた後は開始ボタンで再開します。[レイアウトと検証記録](docs/projector-layout.md)

## APIモード

画面上部の「対戦モード」で「OpenAI 実API」と「ローカル体験」を切り替えられます。初期選択はローカル体験です。API呼び出し中はゲーム時間を止め、失敗時には理由を表示して停止します。再開ボタンで再試行できます。ローカルモードへの自動切り替えは行いません。

- **Agents API**: `POST /v1/agents/sessions`、`environment.type: none`で脱出方針を生成します。ゲームごとにセッションを作り、リセット・ページ離脱で削除します。
- **Decisions API**: `POST /v1/decisions`で現在の状態、Agentsの方針、有効な行動の選択肢から次の行動を選びます。返された選択肢をシミュレーションのルールで再検証します。
- 「接続・判断の詳細」で実際に受信したモデル、Request/Decision ID、confidenceを確認できます。confidenceは勝率ではありません。判断ログでは`OPENAI`と`LOCAL`を区別します。
- ローカルではGit管理外の`.env.local`、Sitesではネイティブの秘密設定`OPENAI_API_KEY`を使用します。キーをブラウザーへ配信しません。

APIの契約、権限、公式資料は[API調査ノート](docs/openai-api-notes.md)、移植内容は[Sites対応ノート](docs/sites-runtime-notes.md)を参照してください。ゲーム状態はブラウザー内で管理します。APIセッションはSitesが確認したユーザーと有効期限付き署名トークンに結び付け、Workerの切り替わりに依存しません。公開マルチプレイヤー用途の不正対策やゲーム進行の永続保存は含みません。

## 検証

```sh
npm test
npm run build
```

デモ前は公開後の **実APIテストを必須** とします。`npm run test:live` でAgentsの方針生成、3回以上のDecisions、扉封鎖後の再判断、セッション削除を実通信で確認し、`npm run demo:ready` が成功してから発表してください。未実施・失敗・古い公開コミットの証跡は合格になりません。[実行手順と合格条件](docs/live-demo-check.md)

シミュレーションは描画から独立しており、ぬこぬこさんを研究室に留めた条件での目標達成・脱出と戦略的な封鎖によるプレイヤー勝利、通常の追尾での接触後の継続と恐怖100での捕獲終了、フレーム間隔によらない進行、自然失効した封鎖と出口認証の区別、恐怖回復、入力検証、一時停止・終了状態をテストしています。API層はリクエスト形状、SSEの正常終了と切断、補助エージェント出力の分離、拒否・質問名の不一致・不正な選択、匿名のステータス参照と認証必須の実API、外部Origin、ユーザー間の分離、署名の改変と期限切れ、別Workerでの継続を検証しています。

サム・追尾・Tibo・隠れ場所を加えた版では55件のテストとWorkerビルドが成功しました。写真参照素材・俯瞰素材・大型カットイン・右列のアイコンUIを含む画面確認と、遅延モックAPIによる停止・リセット境界を検証しています。[今回の検証範囲](docs/sam-chase.md#検証)

## 開発フロー

作業ブランチで変更をcommitし、テスト・ビルド・画面確認後にmainへ統合します。Sitesのソースリポジトリと公開GitHubは同じcommitを同期します。生成物、依存ライブラリ、環境変数、認証情報はcommitしません。API仕様は変更前に公式資料を再確認し、差分をdocsに残します。
